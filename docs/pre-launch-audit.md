# Keshsudha website — pre-launch technical audit (20 points)

Audited: 15 November 2026, against the production build (`next build` + `next start`) at `http://localhost:3000`, commit state of `E:\project_hair` on that date.

How it was audited
- Code inspection of routes, components, config and integrations.
- Live HTTP checks with `bash scripts/audit-http.sh` (status codes, redirects, headers, APIs, full checkout → order page → eBook download).
- Live browser checks with `node scripts/audit-pages.mjs` (headless Chromium: titles, descriptions, canonicals, OG tags, H1s, JSON-LD, images, console errors, internal links) and `node scripts/audit-admin.mjs` (staff login flow).
- `npm run typecheck`, `npm run lint`, `npm test` (18 unit tests), `npm run build`.
- Not available in this environment: a public domain, DNS, Google Analytics property, Google Search Console, Razorpay/Resend/Shiprocket credentials. Anything that depends on those is marked NEEDS EXTERNAL VERIFICATION rather than PASS.

Framework facts (verified in code and build output): Next.js 16.4.6 App Router with Cache Components and Partial Prefetching; `src/proxy.ts` (the Next 16 replacement for middleware); PostgreSQL on Neon via Drizzle; Razorpay hosted checkout; GA4 via `@next/third-parties`; hosting target Vercel (not yet deployed).

## 2. Highest-priority issues found (and what was done)

| Priority | Issue | Fix applied |
| --- | --- | --- |
| High (SEO) | Unknown product slugs returned 200 | `src/proxy.ts` rewrites `/products/<unknown>` to a non-existent route → real 404 with the branded page (verified: `/products/nope` → 404). |
| High (SEO/social) | Default OG image missing on six pages | `defaultOgImage` added to each page's `openGraph`; verified `og:image` present on all 16 pages. |
| High (build) | `new Date()` in product JSON-LD and `usePathname()` in the header blocked prerendering | Fixed `priceValidUntil` constant; header active-link logic moved into a Suspense-wrapped child. Build passes with all marketing pages static. |
| Medium (a11y/SEO) | H1 → H3 jump on `/products` | `ProductCard` takes `headingLevel`; shop page uses H2. |
| Medium (SEO) | 404 page inherited homepage canonical | Root canonical removed; per-page canonicals kept; 404 now has none. |
| Medium (UX/no-JS) | Scroll-reveal sections rendered with `opacity:0` in server HTML | Replaced motion-based reveal with CSS gated on `@media (scripting: enabled)`; content is visible without JS and for crawlers, and nothing mutates `<html>` before hydration (a `js` class or `data-js` attribute both trigger a React 19 hydration warning). |
| Medium (mobile) | Header CTA overlapped the logo on phones | Custom `.btn/.card/.field` classes moved into `@layer components` so Tailwind utilities (`hidden`, `lg:inline-flex`) win. |
| Medium (checkout) | Production without Razorpay keys showed a Pay button that could only fail | Checkout hides online payment and offers COD with a notice when keys are absent; the dev simulator is still refused in production. |
| Medium (spam) | Honeypot answered 400 | Honeypot checked before validation; returns a quiet 200 (verified). |
| Low (3D) | Jar and bottle cap cropped by the camera | Camera pulled back in hero and product viewer; three.js shadow type set to a supported value. |
| Low (admin) | Login page showed the staff nav and a Log out button | Authenticated pages moved to `src/app/admin/(authed)/` with their own layout; login page is bare. Admin pages now call `connection()` so prefetching never evaluates session checks. |
| Low (tooling) | vitest 5 failed to start on this machine; vitest 3 had critical advisories | Pinned `vitest@4` (tests pass, 0 high/critical advisories). |

## 5. Unresolved issues and external dependencies

1. Placeholder business details: support phone and street address in `src/lib/site.ts`; GSTIN and FSSAI licence numbers empty until issued.
2. Placeholder imagery: SVG-rendered WebP product art; replace with photography of the same filenames and 1200×1200 size.
3. Credentials not available here: Razorpay (key id, secret, webhook secret), Resend (API key + verified domain), Shiprocket (API user, pickup location, webhook token), GA4 measurement ID, Search Console token, production `ADMIN_PASSWORD` and `EBOOK_SIGNING_SECRET`.
4. Rate limiting is in-memory per instance; adequate for launch volume, replace with Upstash/Redis if traffic grows or if deployed across many serverless instances.
5. No Content-Security-Policy header yet (Razorpay checkout, GA and inline JSON-LD need an allow-list; a nonce-based CSP conflicts with static prerendering). Recommend a report-only CSP first.
6. Reviews, subscriptions, abandoned-cart emails and customer accounts are intentionally out of MVP scope (see BRD).
7. `npm audit` moderate advisories are confined to dev tooling and require major upgrades of `drizzle-kit`/`typescript-eslint`; revisit monthly.

## 6. Prioritised pre-launch checklist

1. Fill `.env.local`/Vercel env: `NEXT_PUBLIC_SITE_URL`, `DATABASE_URL`, `ADMIN_PASSWORD` (≥ 8 chars, strong), `EBOOK_SIGNING_SECRET` (≥ 32 random chars), Razorpay live keys + webhook secret, `RESEND_API_KEY` + `EMAIL_FROM` on a verified domain, Shiprocket credentials and webhook token.
2. Replace placeholder phone, address, GSTIN/FSSAI in `src/lib/site.ts`; replace product photography.
3. Deploy to Vercel (Mumbai region), point the domain, enable `www` → apex and HTTPS redirects, confirm HSTS preload only after HTTPS is stable.
4. Register the Razorpay webhook (`payment.captured`, `payment.failed`, `order.paid`, `refund.processed`) and place a ₹1 live test order end to end; confirm the email and PDF arrive and the order shows `paid` in `/admin`.
5. Register the Shiprocket webhook; ship one test parcel and confirm tracking updates flow into the order.
6. Create the GA4 property, set the ID, verify `purchase` in DebugView; create the Search Console property, verify, submit `/sitemap.xml`.
7. Run Google's Rich Results Test on `/` and a product page; run Lighthouse on mobile for `/` and a PDP (target LCP < 2.5 s on 4G).
8. Re-run `bash scripts/audit-http.sh https://<domain>` and `node scripts/audit-pages.mjs https://<domain>` against production and keep the output with this document.
9. Review `/privacy` and `/terms` with counsel; confirm the FSSAI food licence and cosmetics licence numbers are printed before the first sale.
10. Set up uptime monitoring on `/api/health` and error tracking (Sentry) before announcing the launch.
